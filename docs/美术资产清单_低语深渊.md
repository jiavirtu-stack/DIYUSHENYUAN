# 《低语深渊》美术资产制作与验收清单

版本：v1.0（团队执行版）
适用范围：首个可玩版本；Godot 4、PC 单人、2.5D 俯视动作 Roguelite。
依据：[需求确认记录](需求确认记录_低语深渊.md)与[策划清单](策划清单_低语深渊.md)。

> 使用方式：每项由负责人认领，按“制作 → 导入 → 游戏内检查 → 验收”推进。将表格中的负责人、状态、链接补齐后作为团队追踪表使用。数量标记为“建议”的内容仍需策划/制作负责人确认，不应视为已锁定的最终需求。

## 1. 项目美术方向

### 已确认

- 采用 2.5D 俯视表现：3D 地面与环境，角色、敌人及部分特效使用面向镜头的 2D 贴图/序列帧。
- 参考用户提供视频的手绘质感、明确轮廓、夸张而易读的动作，以及暖红/赭石与暗环境的对比。视频仅作整体风格与动作节奏参考，具体角色、怪物、场景、符号、UI 和音效均原创。
- 故事发生在隐瞒献祭的沉没村落；玩家为调查员；区域首领为“钟下守夜人”。
- SAN 系统暂缓。当前美术不制作 SAN 数值条、阶段滤镜、SAN 成本提示、幻觉效果或 SAN 归零演出。

### 制作约束

- 建议色彩方向：潮湿石青/灰绿环境、赭红与旧金作为暖色焦点、暗紫/近黑作为污染色。具体色值由风格基准板确定。
- 角色、敌人与危险预警必须靠轮廓、形状和动作可读，不得只靠颜色传达信息。
- 角色锚点统一落在脚底中心；同一动作序列的脚底位置、角色占画面比例和朝向保持稳定。
- 场景细节和纹理对比度低于角色与危险预警；特效不得长期遮住玩家、敌人或攻击范围。
- 灰盒可用于玩法迭代；进入正式内容验收时，主角、敌人、Boss、关键地标和核心 UI 必须替换为原创可交付资源。

## 2. 状态、优先级与完成定义

**状态值**：未开始 / 制作中 / 待导入 / 待验收 / 返修 / 已验收 / 暂缓。
**优先级**：P0 为战斗闭环必需；P1 为首个可玩版本核心内容；P2 为扩充内容；P3 为包装与后续质量提升。

资产只有同时满足以下条件才能标为“已验收”：

1. 文件、尺寸、透明通道/贴图格式与命名符合约定，源文件或可继续编辑的工程文件已交付（适用时）。
2. 已按实际项目导入 Godot，材质、过滤、透明排序、缩放和锚点无明显问题。
3. 已在目标游戏视角及实际战斗画面检查，不只在绘图软件或资源预览窗验收。
4. 动作、轮廓、特效和 UI 信息能支撑策划规则；通过对应验收点。
5. 负责人、文件路径、版本和验收人已登记，修改后版本可追踪。

## 4. 动画交付表

方向数量须与项目确定的朝向控制方案一致。下列帧数是制作起点建议，不是强制规格；动作节奏和判定窗口优先于堆帧。

| 对象 | 必需动作 | 帧数起点建议 | 动画验收重点 |
|---|---|---|---|
| 调查员 | idle、move、attack、dodge、hurt、death | 待机 2–4 帧；其余 4–8 帧/动作 | 攻击起止清楚；闪避有明显位移；脚底稳定；受击能确认方向 |
| 近战敌人 | idle、move、telegraph、attack、hurt、death | 2–6 帧/动作 | 攻击预警先于判定；攻击方向和碰撞范围一致 |
| 远程敌人 | idle、aim、telegraph、release、hurt、death | 2–6 帧/动作 | 瞄准、发射、弹道出现顺序清楚；玩家可反应 |
| 精英 | idle、dash_telegraph、dash、special、recover、hurt、death | 3–8 帧/动作 | 冲刺方向和恢复窗口可读；不同招式的预警不混淆 |
| Boss | idle、各招式 windup/attack/recover、stagger、phase_transition、death | 4–10 帧/动作 | 招式关键姿态可辨；阶段转换明确；预警、攻击判定和恢复时间匹配 |

**序列帧提交时同时交付**：帧顺序/帧数、推荐播放帧率、循环与否、锚点位置、朝向说明、命中/预警对应帧。建议帧率：角色 8–12 FPS、蓄力/攻击关键段 10–15 FPS、特效 12–18 FPS；在游戏内实测后确定。

## 5. 文件、目录与导入规范

### 推荐目录

```text
assets/lowwhisper/characters/player/
assets/lowwhisper/characters/enemies/
assets/lowwhisper/characters/boss/
assets/lowwhisper/environment/tiles/
assets/lowwhisper/environment/props/
assets/lowwhisper/vfx/
assets/lowwhisper/ui/icons/
assets/lowwhisper/ui/screens/
assets/lowwhisper/audio/sfx/
assets/lowwhisper/audio/music/
```

### 文件命名

统一使用小写英文、下划线、版本号：`类别_对象_动作_方向_v版本.扩展名`。示例：

- `char_investigator_attack_front_v01.png`
- `enemy_corrupted_villager_telegraph_front_v01.png`
- `vfx_bellkeeper_sweep_v01.png`
- `ui_card_icon_ritual_01_v01.png`

动画序列建议使用 Godot 可直接识别的编号帧，例如 `..._000.png`、`..._001.png`，并附一份帧序说明。不要用中文、空格或“最终版2”等临时名称。

### 格式与导入

- 透明角色、图标、特效：优先 PNG + RGBA；无透明需求的背景/底图可采用项目认可的格式。
- 角色和图标过滤方式以实际像素密度检查为准；手绘非像素风通常先试 Linear。细线、渐变、透明边缘须在 Godot 中检查压缩伪影和黑边。
- 可平铺地面才启用 Repeat；需要远景缩放的贴图按实际效果评估 mipmap。导入参数由技术美术/程序确认并记录，不将建议值当作固定要求。
- 角色图集统一帧尺寸、透明边距和脚底锚点；避免每帧自动裁切后导致跳动。

每批资产附 `ASSET_SOURCES.md`，记录资产 ID、作者/生成方式、源文件、尺寸、帧数、锚点、提示词摘要（如使用生成模型）、授权/来源、Godot 导入参数及当前版本。生成图必须人工检查手指/肢体、轮廓连续性、帧间一致性和透明边缘，再进入游戏。

## 6. 制作顺序与关卡协作

1. **先定基准**：完成 ART-00，约定角色占屏高度、地面网格、镜头、轮廓粗细与色彩。
2. **先跑战斗闭环**：制作 ART-01 至 ART-05 的最小可用版本；主角、敌人与主动卡通过灰盒验证后再扩充帧数和细节。
3. **边搭关卡边补环境**：ART-10 先从灰盒房间的真实模块需求反推，避免先画一整套用不到的地砖。
4. **锁定内容后批量生产**：普通敌人、卡牌、事件和遗物的数量/规则定稿后，再按 ART-07/08/12/16 批量制作。
5. **Boss 最后冻结**：在技能节奏、判定和场地尺寸确定后制作 ART-14/15，预警形状与程序判定共用同一规格说明。
6. **统一验收**：每次新资产或关键修改都在目标窗口尺寸、实际镜头、实际灯光和实际缩放下核查。

## 8. 暂缓与范围边界

- SAN 暂不制作任何数值 UI、状态滤镜、幻觉、相关特效或失败演出。
- 单区 8–12 节点、12 张卡、3 件遗物、约 6 个事件、3 种普通敌人等均为当前内容规划建议量；开工前可由团队根据工期确认或调整。
- 不制作参考视频中的具体角色、怪物、构图、符号或 UI；以其手绘质感和动作可读性为参考，原创设计。
- 首版不扩展多区域大陆、多人角色、复杂过场或与已确认玩法无关的装饰资产。
