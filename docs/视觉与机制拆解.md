## 直接可观察事实

### 镜头与构图

- 画面为固定的高位斜俯视战斗视角，地面深度从画面下方向后方收窄；顶端背景区域占画面比例较小。
- 镜头在交战期间大体稳定，Boss 与玩家的相对位置、场地纵深始终清楚。视频不足以测量精确相机角度、焦距或世界单位尺寸。
- 战斗画面为宽屏，战场主体居中，玩家体型远小于 Boss；Boss 的肢体和特效会覆盖场地中央的大块区域。

### 场景

- 竞技场是暖红/赭色石砖平台，外围有不规则草地或植被边缘，平台外是深色环境。
- 中央地面存在大型圆形法阵与放射式装饰；多块砖缝、污渍和边缘装饰让地面不显得平整单调。
- 后方中央有高耸的石质拱门/仪式门，门上有圆形装饰；粗大锁链横跨门后上方区域。
- 两侧后景有低亮度烛火/暖色光点和植物；边界附近可见零散石块、骨状或骸骨装饰。

### 角色与 Boss

- 玩家是画面下半部的小体型角色，以脚底落点在地面移动；多个方向移动时角色仍能从高机位辨认。
- Boss 体型明显大于玩家，呈植物/枝蔓与大型口部的混合轮廓，中央有高对比的深色口腔或核心。
- Boss 会改变姿态、伸展枝蔓或触须，攻击时伴随显著的明亮粒子和大范围地面效果。
- 仅凭稀疏关键帧无法可靠判断所有动画帧数、碰撞形状或精确受击判定。

### 技能、反馈与战斗流程

- 画面能看到地面上的彩色圆形/区域标记，以及沿多个方向移动或扩散的亮色弹体/特效。
- Boss 发动大范围动作时通常伴随姿态变化与高亮特效；从画面可以观察到存在一定可读的攻击提示，但无法仅凭抽帧测量完整预警时长。
- 战斗中出现明显的粒子爆发、地面冲击/弹幕效果、受击闪光与血迹类视觉反馈；视频音轨未在本分析中检查，不能据此推断具体音效。
- 约 34 秒出现覆盖游戏画面的说明/教程面板；约 42 秒出现由图标组成的构筑/选择界面；约 47 秒出现战斗后的获取提示；约 55 秒出现一组增益/构筑展示。由此可见视频含战斗外成长或奖励环节。

### UI

- 战斗 HUD 位于画面边缘，左上可见玩家状态图标，画面底边中央附近可见 Boss 血条；部分阶段右侧有目标/阶段提示。
- 战斗之间切换到覆盖式的暗色面板和图标网格。UI 整体与暗红/黑色画面协调。
- 截图不足以准确辨认全部文字、数值、按键绑定或 UI 交互规则。

## 推测与 MVP 设计选择

以下不是视频能够直接证明的机制，而是为可控、可测试的单 Boss MVP 提出的实现方案：

1. 用 3D 石砖地面和正交相机建立稳定纵深；玩家与 Boss 使用面向摄像机的原创精灵，碰撞与排序以脚底位置为基准。
2. 竞技场做成有边界的圆角平台，外围以深色背景、草地和原创碎石/植被装饰建立落差感；背景拱门和链条与战斗地面分层。
3. 先实现固定镜头，不推测或硬编码视频无法测得的精确相机角度；通过可调相机参数对照关键帧。
4. Boss 先采用可读的状态机和三种带预警攻击：追踪地刺、前方扇形冲击、留出安全缺口的环形弹幕。预警结束时间必须与实际命中时刻一致。
5. MVP 闭环采用单局胜败、重试和三选一奖励。视频出现了构筑/奖励 UI，但具体奖励规则未知，因此奖励内容由 MVP 自行配置。
6. 输入、伤害、无敌帧、击退和提示范围都由项目内参数配置；通过测试场景核对预警与判定，而不是从画面帧数猜机制。

## 透视实现方案

### 方案 A：3D 地面 + 正交相机 + 面向镜头的角色精灵（选用）

- 地面和背景建筑使用有纹理的 3D 网格；角色和 Boss 用透明精灵/图集面向相机呈现。
- 优点：地面坐标、深度排序、投影到地面的预警、碰撞和相机变换都能共用同一空间；容易保持斜俯视比例且不依赖透视缩放改变角色大小。
- 缺点：需要处理精灵透明排序、阴影与地面透视比例。
- 选择理由：参考画面的平台透视清楚、背景有明显前后层次，同时角色轮廓近似始终朝向玩家视点；该方案方便将预警范围和地面判定放在统一坐标系。

### 方案 B：2D 伪透视

- 全部内容使用 2D 节点；地面、法阵和装饰通过缩放、形变或预绘透视背景伪造纵深。
- 优点：制作和 UI 合成较直接，适用于固定画面、少量深度交互。
- 缺点：移动时需要自行维护地面投影、遮挡关系、预警透视与角色大小变化；动态移动和技能碰撞更容易出现画面与逻辑不一致。
- 结论：本项目按阶段文档选用方案 A，方案 B 不作为当前工程基线。
