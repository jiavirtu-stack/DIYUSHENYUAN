# 《低语深渊》策划与开发清单

版本：首版执行清单 v0.1；状态：可进入原型拆解。数值以测试结果为准，不把 GDD 示例数值当作最终平衡。

## 0. 当前确认边界

- [x] Godot 4、PC 单人、2.5D 俯视动作 Roguelite。
- [x] 沿用当前已验证 MVP 的移动、闪避、近战、镜头和战斗反馈技术基础。
- [x] 美术方向对齐用户参考视频的手绘质感与动作可读性；所有新角色、地标、UI 和音效做原创版本。
- [x] 故事采用沉没村落隐瞒献祭；调查员追查真相；区域 Boss 为钟下守夜人。
- [x] 首版目标是一片区域、8–12 个连通节点，局长目标 10–15 分钟。
- [x] 卡组槽位 4 主动 + 3 被动；满槽直接替换；首版不做主世界随机遭遇战。
- [x] HP 归零结束本局；局内状态重置，图鉴/解锁/知识等局外进度保留；不做“两条命”。
- [x] SAN 暂缓：当前不实现、不配数值、不纳入死亡条件。

## 1. P0：战斗手感与技术基线

**目标**：把现有战斗 MVP 定为《低语深渊》的输入、相机和命中技术基线；用调查员、1 种敌人、1 张主动卡完成至少 3 分钟连续战斗。

- [ ] P0-01 建立新游戏入口/场景命名与资产命名规则；旧原型保持可回滚、可单独打开。
- [ ] P0-02 锁定 2.5D 摄像机、逻辑分辨率、Sprite3D 地面锚点、角色屏幕高度和竞技场边界。
- [ ] P0-03 调查员移动、鼠标瞄准、普攻、闪避、受击和死亡接入新的资源路径；先沿用现有控制器结构。
- [ ] P0-04 制作 1 个灰盒战斗房与 1 个普通敌人；验证导航/追击、攻击前摇、碰撞和死亡。
- [ ] P0-05 制作 1 张主动卡：数据 Resource、快捷键、冷却、效果、图标占位、伤害日志。
- [ ] P0-06 连接玩家 HP、敌人 HP、击退、无敌帧、命中停顿、震屏、音效与伤害显示。
- [ ] P0-07 提供 3 分钟可持续战斗测试场景；记录命中、受击、闪避无敌帧和重开。
- [ ] P0-08 用正式原创美术替换 P0 灰盒玩家、敌人和技能；冻结前景/后景层级与读图规则。

**P0 验收**：连续战斗 3 分钟无阻断错误；攻击判定与视觉方向一致；闪避能躲开明确预警；角色/敌人倒地后状态正确；失败后可重开；无默认 Godot 图标充当正式资源。

## 2. P1：卡牌数据与局内构筑（暂不接 SAN）

- [ ] P1-01 建立 CardData Resource：`id/name/school/type/rarity/cooldown/effect_id/effect_params/icon/description`。
- [ ] P1-02 将主动卡映射到 Q/E/R/F；探索 E 交互、战斗 E 施法采用状态上下文，避免同场景误操作。
- [ ] P1-03 建立 4 主动 + 3 被动装备栏、获取卡牌、满槽替换、替换对比和主动/被动区分。
- [ ] P1-04 创建 12 张首版卡，按物理/法术/召唤/禁忌四学派分布；当前所有 SAN 字段留空或禁用。
- [ ] P1-05 明确至少 3 组有机制差异的协同，例如闪避反击、控制连击、召唤保护；不要只堆伤害数值。
- [ ] P1-06 建立卡牌描述规则：范围、持续时间、冷却、目标数、触发条件均能被玩家预判。
- [ ] P1-07 用脚本或测试场景检查技能冷却不能为负、替换/移除正确、被动效果卸载正确、重开时不残留。

**P1 验收**：玩家能在一局内获得和替换卡牌；三组构筑产生不同打法；卡牌只通过探索主获取；不使用 SAN 仍能闭合战斗循环。

## 3. P2：探索地图、互动和传送门

- [ ] P2-01 建立 8–12 个房间/区块模块与入口、出口方向数据。
- [ ] P2-02 固定主路径：出生点 → 若干分支/事件 → 休息/奖励 → 首领门；随机填充可选节点。
- [ ] P2-03 实现固定种子生成与地图可达性验证；校验失败时重抽并记录原因。
- [ ] P2-04 保证至少一条不依赖消耗品的路线抵达 Boss；普通门与首领门可辨识。
- [ ] P2-05 实现迷雾或未探索节点显示、Tab 地图、已完成/未完成/危险节点标记。
- [ ] P2-06 实现 E 交互提示、一次性领取、防重复领取和事件结果保存。
- [ ] P2-07 制作约 6 个事件；每个事件有前提、选项、结果、一次/每局限制和收益预告。
- [ ] P2-08 首版休息点最多 1 个；SAN 暂缓期间只测试 HP 恢复或非数值剧情交互，具体规则待测。
- [ ] P2-09 传送门预览危险级别，进入战斗时保留生命、卡牌、遗物、种子和节点状态；胜利后回到正确探索节点。

**P2 验收**：给定同一种子可复现同一地图；所有关键节点可达；每个事件只能按规则触发；战斗往返不丢状态；地图不会生成软锁。

## 4. P3：内容、Boss 与局外成长

- [ ] P3-01 完成三种普通敌人的移动/攻击策略：近战腐化村民、远程低语眼、留场地形的泥沼爬行者。
- [ ] P3-02 完成精英“守夜执事”：冲刺与召唤使用不同预警，明确恢复窗口。
- [ ] P3-03 完成钟下守夜人两阶段：阶段一钟摆横扫/定点钟鸣；阶段二增加影仆召唤或扩大地面风险圈。
- [ ] P3-04 所有 Boss 招式包含前摇、有效判定、后摇、可乘之机；预警和命中形状共享参数。
- [ ] P3-05 添加三件遗物；效果、触发条件、叠加和每场限制写入数据，不写死在角色脚本。
- [ ] P3-06 建立营地、卡牌/遗物图鉴、知识奖励、解锁与设置存档。
- [ ] P3-07 实现 HP 死亡结算：死因、抵达区域、构筑摘要、知识奖励、重开；局内数据清空、meta 数据保留。
- [ ] P3-08 实现 Boss 胜利结算、完整结束演出与回营地/继续路线。

**P3 验收**：从开始调查至死亡或胜利可完整跑通；每次重试重置敌人/计时器/地图状态；局外解锁保留；一局时长接近 10–15 分钟目标。

## 5. P4：测试、平衡与交付

- [ ] P4-01 自动测试：移动、碰撞、普攻、闪避无敌帧、卡牌冷却、地图可达、事件一次性、传送门往返、Boss 状态与重试。
- [ ] P4-02 新玩家体验：观察能否自行完成移动、攻击、闪避、获得卡、进入门和重开，不口头提示。
- [ ] P4-03 逐项记录首次死亡原因、卡牌来源理解、事件选择和是否愿意再开一局；小样本只做迭代线索。
- [ ] P4-04 检查资源缺失、信号重复连接、残留敌人、重复奖励、场景节点路径和粒子峰值。
- [ ] P4-05 在目标分辨率下采样性能；未实测不写“稳定 60fps”。
- [ ] P4-06 Windows 导出模板可用后建立导出预设，实际运行导出结果。
- [ ] P4-07 输出新手指南、键位、资产清单、参数表、已知问题与测试记录。

## 6. 策划交付清单

- [ ] 每种卡牌、遗物、事件、敌人、Boss 技能都有独立数据表和唯一 ID。
- [ ] 每个事件明确奖励/代价、一次性规则和预览文案。
- [ ] 每张卡能说明触发方式、目标、范围、冷却和持续时间；SAN 内容不进入首版。
- [ ] 每个敌人至少有一种可辨攻击节奏和一个稳定克制方法。
- [ ] 每个随机节点都有安全的撤退/放弃路径，生成器不阻断必经路线。
- [ ] 平衡表记录每次测试版本与参数变化；不把示例值直接定为正式数值。
- [ ] SAN 作为独立后续议题，不在本轮卡牌/地图/死亡验收中暗中依赖。

## 7. 首版风险与控制

| 风险 | 控制方式 |
|---|---|
| 当前 Boss 战 MVP 场景偏仪式竞技场，和沉没村落内容不一致 | 复用控制器/相机/战斗基础；新建低语深渊场景与资产路径，旧场景保留作回归测试 |
| 地图模块拼接出现断路或必经消耗锁 | 先构建固定主路线，再插入分支；每个种子运行可达性检查 |
| 4 主动卡与探索按键冲突 | 状态上下文输入；菜单/对话暂停战斗输入 |
| 卡牌协同变成纯数值提升 | P1 至少三组改变触发节奏/控制/召唤行为的构筑 |
| SAN 尚未设计但影响卡牌成本和叙事 | 首版不以 SAN 作为卡牌/死亡依赖，系统字段预留、整体后接 |
| 2.5D 场景和 Sprite3D 排序不稳 | 固定地面锚点、角色前后景测试、预警网格直接落在战斗地面 |

## 8. 范围外（首版不做）

- 多人、开放世界、大量剧情分支、3–5 层完整大陆。
- 完整 SAN 阶段、幻觉、SAN 消耗/恢复、SAN 归零结算。
- 多名可玩调查员、6 主动卡、卡牌暂存、复杂商店和中途读档。
- 永久伤害无限叠加、强制反向控制、无预警瞬杀。
